## 1. 実装したこと / What was implemented

- ネパール語本文は **ノートブックの外** の副ファイルに置きました。
  `assets/i18n/ne/notebooks/*.ne.md`（16 冊）と `assets/i18n/ne/docs/*.ne.md`（12 文書）。
  用語と表記の基準は `assets/i18n/ne/terminology.md` です。
  The Nepali prose lives in sidecar catalogs keyed by cell id (notebooks) or by heading
  (documents), so translation, review and re-application stay separate, repeatable steps.

- 差し込みは 2 本のスクリプトで行います。
  `assets/scripts/apply_nepali_translations.py`（ノートブック、セル ID 指定）と
  `assets/scripts/apply_nepali_docs.py`（文書、見出し指定）。
  どちらも `<!-- ne:begin … --> … <!-- ne:end -->` の印で囲んだ領域だけを書き換えるので、
  **2 回目以降は 1 バイトも変わりません**（冪等）。
  Both appliers rewrite only the inside of a marked region, so a second run is a no-op; a heading
  that no longer exists is an error rather than a silent loss of translation.

- コードセル、セル ID、出力、実行回数は一切変更していません。もとの日本語・英語の本文も
  バイト単位で同じです（第 4 節の検証を参照）。
  Code cells, ids, outputs and execution counts are untouched, and the original Japanese/English
  prose is byte-identical.

- 点検ツール `assets/scripts/check_nepali_coverage.py` を追加しました。セルごとの未翻訳、
  除外の妥当性、ヒンディー語形・プレースホルダの混入、印の外にあるデーヴァナーガリーを報告します。
  A coverage checker reports missing cells, justified exemptions, Hindi/placeholder leakage and
  Devanagari outside a marked region. It never writes.

- 三言語 PDF は新しい書き出し `assets/scripts/export_trilingual_pdf.py` で作ります。
  既存の `export_explanations_pdf.py`（ReportLab）は **変更していません**。
  A new exporter builds the tri-language PDFs; the existing ReportLab exporter is unchanged.

- `assets/scripts/inspect_pdf_pages.py` に `--languages ja,ne` を追加しました。全ページを描画した
  うえで、ネパール語が本文に入っているか、**単語の途中に空白が入って検索できなくなっていないか**
  を点検します。
  The page-by-page inspector gained `--languages ja,ne`: it renders every page and checks that the
  Devanagari text layer is present and not split by inserted spaces.

- `assets/tests/test_nepali_localization.py` を追加しました（30 件）。カタログの対応、冪等性、
  もと本文の保持、ヒンディー語・プレースホルダの不在、PDF のテキスト層を検証します。
  Thirty new tests cover catalog alignment, idempotency, preservation of the original text,
  forbidden content and the PDF text layer.

### 組み方 / How the pages are laid out

- 見出しは 日本語 → English → नेपाली を 1 つの見出しにまとめて組んでいます。目次も同じ順で
  1 行に並べ、ページ番号は右端に置いています（3 言語が 1 行に入らない行だけ折り返します）。
  Headings merge the three languages, and each contents line lists them in the same order with the
  page number on the right (a long entry simply wraps).
- ページ番号は 2 回組みで求めます。1 回目の目次は `visibility:hidden` で組むため、目次の文字も
  PDF のテキスト層に残ります。そこで本文の先頭にだけ現れる目印（`BODYSTARTOFDOCUMENT`、透明・
  1 pt）を置き、**そのページより後ろだけ**を見出しの検索対象にしました。目印がないと目次自身の行に
  一致して番号が狂います（この回の途中で実際にそうなり、番号が二重に出ました）。
  Page numbers come from the two-pass build. The first pass lays the contents out with
  `visibility: hidden`, which still leaves its text in the PDF text layer, so an invisible 1 pt marker
  (`BODYSTARTOFDOCUMENT`) sits at the start of the body and heading lookups search **only after** that
  page. Without it the lookup matched the contents page itself and the numbers came out wrong and
  doubled — which is exactly what this pass hit before the marker was added.
- 表・図のキャプション・「気づいてほしいこと」・問いも 3 言語です。図は**既存の画像をそのまま**
  使い、横長の図は A4 横向きのページに置きました。
  Tables, figure captions, "what to notice" and questions are trilingual; the figures are the
  existing images, unchanged, with wide ones on landscape A4 pages.
- ノートブックの PDF は見出しが 3 言語で統合されるので、目次も 3 言語です。文書の PDF
  （`START_HERE.md` など）は、ネパール語を各節の末尾に `### नेपालीमा` の見出しでまとめているため、
  目次は 日本語＋英語の節構成のままです。ネパール語の本文は各節の直後にあり、検索できます。
  In the notebook booklets the headings merge across the three languages, so the contents are
  trilingual too. In the document booklets (`START_HERE.md` and friends) the Nepali text sits at the
  end of each section under a `### नेपालीमा` label, so the contents keep the Japanese + English
  outline while the Nepali prose is present and searchable right after each section.
- セルの実行出力・スタックトレース・講師用解答は入れていません（既存の方針どおり）。
  No cell outputs, stack traces or instructor answers, as before.

## 5. 途中で分かったこと（記録）/ Findings worth recording

### 5.1 ReportLab ではデーヴァナーガリーを検索可能にできない

`reportlab==5.1.0` は `uharfbuzz` を入れると字形の整形はできますが、本文は私用領域
（`\ue000` など）で書かれ、`प्रशिक्षण` を検索できません。
`ParagraphStyle(shaping=1)` を使っても同じでした。
ReportLab can shape Devanagari once `uharfbuzz` is present, but it writes the text layer in
private-use code points, so Nepali words cannot be found. The existing Japanese + English
exporter was therefore left alone, and the tri-language booklets are printed through Chromium.

### 5.2 Chromium も「大きさ次第」で単語の途中に空白を書く

Chromium の PDF 出力は、字形の位置調整（abvm: above-base mark positioning）が入ると
**実際の空白文字を単語の途中に書き込みます**。さらに、フォントサイズが 1.5 pt の倍数でないと
同じことが起きます。実測で分かった条件と対策は次のとおりです。

- `font-feature-settings: "abvm" 0` を入れると、字形はほぼ変わらず（20 pt の見本で平均画素差
  0.05/255）本文が正しくなります。
- 文字サイズは 6 / 7.5 / 9 / 10.5 / 12 / 13.5 / 15 / 16.5 / 18 pt では正しく、8 / 9.5 / 10 / 11 /
  11.5 / 12.5 / 13 / 14 / 16 pt では崩れます。そこでネパール語の各要素の大きさを
  **1.5 pt の倍数に固定** しました（本文 10.5 pt、見出し 12 / 13.5 pt、表・注 9 pt）。

Chromium writes a real space glyph inside Devanagari words whenever above-base mark positioning
shifts a mark, and also at font sizes that are not multiples of 1.5 pt. Disabling `abvm` keeps the
rendered glyphs effectively identical and, together with pinning every Nepali size to a multiple of
1.5 pt, restores a clean searchable text layer. `inspect_pdf_pages.py --languages ja,ne` fails the
run if that ever regresses.

### 5.3 図は 1 枚も作り直していない

生成済みの PNG / SVG をそのまま読み込んでいます。SVG は既存の PNG 代替を使う既存の規則に従います。
Every figure is the existing file; SVGs reuse the pre-existing PNG fallback exactly as before.

## 7. 既知の限界 / Known limitations

- ネパール語の文章は**ネイティブ校閲を受けていません**。用語は `terminology.md` に固定し、
  ヒンディー語形（`है` / `करना` / `नहीं` / `होता`）とプレースホルダはテストで禁止していますが、
  言い回しの自然さは校閲が必要です。
  The Nepali prose has **not had a native review**. Terminology and the ban on Hindi forms and
  placeholders are enforced by test; naturalness still needs a native reader.
- 文書の翻訳は**節単位**です。ノートブックはセル単位で全文を訳していますが、長い文書
  （`README.md`、`COURSE_SYLLABUS.md`、`installation.md`）は各節の要約＋表の訳で、
  原文の全段落を逐語訳したものではありません。
  Documents are translated **per section** (summary plus translated tables), while the notebooks
  carry cell-by-cell full text. This is a deliberate scope choice, not an oversight.
- 表記の揺れが 2 種類だけ残っています。`निर्देशाङ्क`（30 箇所）と `निर्देशांक`（5 箇所）、
  `सह्यता`（15 箇所）と `सहनशीलता`（1 箇所）です。どちらも正しいネパール語なので勝手に書き換えず、
  `assets/i18n/ne/terminology.md` の「Variants left for the native review」に件数付きで記録しました。
  Two orthographic variants remain (`निर्देशाङ्क`/`निर्देशांक`, `सह्यता`/`सहनशीलता`). Both are valid
  Nepali, so they are recorded with counts in the glossary rather than rewritten unilaterally.
- 図の中の文字は画像の一部なので検索できません（既存の限界と同じ）。
- PDF は合計で約 56 MB 増えます。既存の 6 冊と同じくリポジトリに含めています。
- `submissions/day05/Day05_Report_Template.md` の見出し番号は `## 4.` `## 5.` が 2 回ずつ
  現れる既存の誤りです。今回の作業範囲外なので**直していません**が、翻訳の差し込みは
  見出し本文（`## 4. YOLO と PatchCore の比較` 等）で行っています。
  The Day 5 report template numbers `## 4.` and `## 5.` twice. That pre-existing slip is out of
  scope and left as it is; the Nepali blocks are anchored on the heading text, not the number.

## 9. ネイティブ校閲のチェックリスト / Native-review checklist

1. **用語** — `assets/i18n/ne/terminology.md` の対訳（特に「異常検知」「較正」「しきい値」
   「偽陽性／偽陰性」「学習／推論」）が工場の現場語として自然か。
2. **数字と単位** — 0.3 mm、1,300 mm、±0.5 mm、8 ビット、99.73 %、score の説明が読みやすいか。
3. **命令の丁寧さ** — です・ます調の統一、`〜してください` の使い分け。
4. **Day 5 の凍結表現** — 「スコアは確率ではない」「試験データでしきい値を調整しない」が
   弱まっていないか。
5. **表の見出し** — ネパール語の表で列の意味が通るか（特に `विषय | विवरण`）。
6. **PDF の見た目** — 表のセル内で語が不自然に折り返していないか、見出しの 3 言語が
   読みやすい順か。
