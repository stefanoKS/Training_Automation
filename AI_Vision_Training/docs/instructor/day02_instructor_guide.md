### 説明する概念 / Key concepts

| 概念 / Concept | 説明の要点 / Key message |
|---|---|
| 変数 | 名前の付いた箱。`=` は「入れる」、`==` は「等しいか」 |
| 型 | `int`（整数）/ `float`（小数）/ `str`（文字列）/ `bool`（真偽） |
| 真偽値 | `True` は「**条件を満たす**」、`False` は「**満たさない**」。正しい／間違いではない |
| 小数の誤差 | `100.3 - 100.0` の表示は `0.29999999999999716`。表示は `round`、比較は「決めた桁で丸めてから」か「許容誤差つきの不等号」。**不等号だけでは誤差は消えない** |
| 単位と丸め | 単位（mm・cm）と、2 進数の表現誤差と、丸めの方針は **別の話**。規格の境界は宣言した値のまま使い、広げて通さない |
| 条件分岐 | `:` と **一貫したインデント** が必須（4 文字を推奨）。**最初に当てはまった枝だけ** 実行 |
| 関数 | 仮引数（定義側の名前）と引数（呼ぶ側の値）→ 処理 → 戻り値。**1 か所直せば全部直る** |
| 例外 | `try` / `except`。**エラーを隠さず記録する**。`input()` の値は文字列で、`float()` は失敗しうる |
| 2値化 | しきい値は **人間が決める**。`THRESH_BINARY_INV` では **しきい値以下が白（前景）**。この演習は管理された背景の暗いマークが対象 |
| 輪郭と面積 | 輪郭は **境界**。`contourArea` は図形としての面積（画素²）で、前景の画素数とも mm² とも同じではない |
| 校正 | px/mm は **撮影条件で決まる**。同じ平面・歪み小・倍率一定が前提。動かしたら校正し直す |

### よくある誤解 / Common beginner misunderstandings

| 誤解 / Misunderstanding | 実際 / Reality |
|---|---|
| `=` は「等しい」 | 代入。比較は `==` |
| `//` は「整数部分を取り出す」 | **切り捨て除算**。商を下（マイナス無限大の向き）に丸めるので `-7 // 2` は `-4`。小数にも使え、`7.0 // 2` は `3.0` |
| `True` は「正しい」 | **条件を満たす** という意味。条件が `False` でもプログラムの誤りとは限らない |
| インデントは見た目だけ | **文法**。同じブロックの中で量がそろっていないとエラー（4 文字を推奨） |
| `0.3` は正確に表せる | 2 進数では表せない。誤差が出る。丸めの方針を先に決める |
| 不等号にすれば比較は安全 | 誤差は消えない。丸めた結果、境界のすぐ外が内側に入ることがある |
| `except: pass` で安全 | **危険**。エラーが消えて原因不明になる |
| `input()` の値はあとで見返せる | 画面にしか出ない。**自分で記録しないと再現できない**。数字以外は `float()` で `ValueError` |
| `cv2.imread` は失敗すると例外 | `None` を返す。**必ず確認** |
| `cv2.imwrite` が `False` になるのはフォルダが無いときだけ | **書き込み権限** や **拡張子と形式の不一致** でも `False` になる |
| OpenCV と Matplotlib の色順は同じ | OpenCV は **BGR**、Matplotlib は RGB。変換が要るのは **BGR の配列** だけ（PIL で開いた RGB 写真はそのまま） |
| しきい値を変えれば必ず領域の数が変わる | 変わるときも変わらないときもある。**T に依存する出力**（マスク・前景画素数・輪郭）と、**依存しない出力**（元画像・校正値）を分けて説明する |
| 輪郭の面積は前景の画素数と同じ | 輪郭は **境界**。`contourArea` は図形としての面積で、画素数の記録ではない |
| 輪郭の面積はそのまま mm² | 画素² であって mm² ではない。`px_per_mm ** 2` で割るのは、画素が正方形で、同じ平面で、歪みが小さいときだけ |
| 画素の番号が整数なら位置も整数だけ | 重心やエッジは **サブピクセル** で推定できる。ただし推定値には不確かさがある |
| 広角レンズでは校正測定は無理 | 無理ではない。**歪み補正** か **領域ごとの校正** を使う。だめなのは補正せず 1 つの倍率を全面に当てること |

## 理解度チェックの解答例 / Model answers

**（受講者には渡さないでください / do not hand these to learners）**

### ノートブック 01

1. `=` は **代入**（箱に入れる）、`==` は **比較**（等しいかの判定）。
2. コンピュータは小数を **2 進数** で表すため、`0.3` は正確に表せない。
   `100.3 - 100.0` の表示は `0.29999999999999716` になる。不具合ではない。
   表示は `round()` で丸め、比較は「先に決めた桁で丸めてから」か「許容誤差つきの不等号」で行う。
   不等号だけでは誤差は消えず、丸めた結果、境界のすぐ外の値が内側に入ることがある。
3. `print(a, b)` は **スペース区切りで並べて表示**。`print(a + b)` は **足し算** をしようとして
   `TypeError`（文字列と数値は足せない）。
4. **変数名の綴り** と、**その変数を定義したセルを実行したか**。
5. 読みやすく、単位（`_mm`）まで分かる。後で自分や他人が読んでも意味が分かる。

補足（よく出る質問）:
- `//` は **切り捨て除算**。`-7 // 2` は `-4`、`7.0 // 2` は `3.0`。
- `True` / `False` は「条件を満たす / 満たさない」。正しい / 間違いではない。

### ノートブック 02

1. `:` が無いと `SyntaxError`。
2. **最初に当てはまった枝だけ** 実行され、残りは飛ばされる。
3. ① 同じコードを繰り返さない ② 名前で意味が分かる ③ 修正が 1 か所で済む。
4. `continue` は **その回の残りを飛ばして次の要素へ** 進む。
5. エラーが **見えなくなる**。データが壊れていても気づかず、原因の特定が不可能になる。

補足:
- ループの図（12.xx、規格 12.50 ± 0.10）と Part 2 のコード（100.xx、規格 100.0 ± 0.5）は **別のデータ**。NG の位置も別。
- 関数の結果は **測定値・基準値・許容差の 3 つ** で決まる。図の例は 12.55 / 12.50 / 0.10 → 差 0.05 → OK。
- 「有効入力の割合 66.7%」は **6 件のうち 4 件が数値として読めた** 割合。検査の再現率（TP ÷ (TP + FN)）ではない。

### ノートブック 03

1. OpenCV は **BGR**、Matplotlib は RGB。BGR の配列を変換しないと赤と青が入れ替わる。逆に、もともと RGB の画像（PIL で開いた写真）を変換すると入れ替わる。
2. **エラーにならない。`None` を返す。** 必ず `None` チェックをする。
3. `THRESH_BINARY_INV` は **しきい値以下を白（前景）**、しきい値より大きい画素を黒にする。
   `findContours` は白い前景を探すので、暗い欠陥を白にして渡す（図のパネル ③ がそのマスク）。
4. **誤検出（偽陽性）が増える。** この演習は管理された背景の暗いマークが対象で、明るさのムラまで前景に入る。
   照明や背景が違えば同じしきい値が最適とは限らない。
5. 1 ピクセルが何 mm かは **カメラと物体の距離** で変わる。校正していない画像の px は、
   mm に換算する根拠が無い。校正は **同一平面・歪みが小さい・倍率が一定** という前提の上でだけ全体に使える。

補足（測定の確認について）:
- 校正に使った基準線を測り直しても **計算の確認** にしかならない。別の位置・別の向きの線（50 mm）が合えば、**同じ合成画像の中での換算の一貫性** が確認できる。
- それでも、視野の端・他の向き・他の距離・レンズ歪みまでは保証しない。実際の測定では複数の位置と向きで確認する。
